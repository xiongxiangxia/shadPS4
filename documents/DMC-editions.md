# DmC 专用实验与根因诊断：两个独立版本

仅针对当前 fork 的 Windows 实验分支。兼容改动不是通用模拟器修复，不准备作为上游通用输入行为提交。原始游戏文件不修改。

## 第一版失效与入口修正

`ad7dddb0` 的构建已成功，但用户普通日志显示 `Bool opcode mismatch; experiment disabled`，且没有意图／重试记录；因此这次没有验证到兼容重试实际执行。第一版误将 `0x58880` 作为 BoolVariable 的入口。

重新追踪解释器初始化：`0x6daa8` 将表基址设为 `0x3960040`；`0x6e115` 从 `0x2f975e8` 读取函数成员指针（重定位目标 `0x55b90`、调整值0），`0x6e12a` 写入表偏移 `0x2d0`，即 opcode `0x2d`。修正版挂钩 `0x55b90`，保留运行时检查；没有删除保护强行启用。

普通日志增加有界阶段记录：入口验证、枪长按属性识别、射击意图、控制器字段、已有缓冲、首次重试、蓄力事件条件及入口选中、charge 标志非零。它们用于确认实际执行阶段，不代表已经证明所有动作和计时都正确。诊断版不受这次修正影响。

## COMPAT-experimental：先测试玩法

专用编译开关 `ENABLE_DMC_CHARGE_COMPAT=ON`。此产物默认启用；`SHADPS4_DMC_COMPAT=0` 可禁用，必须重新启动模拟器。与 F9 无关。不安装重诊断探针，游玩时不要按 F9。

把 exe 和两个 cmd 放入现有模拟器目录（先备份旧 exe）。双击 `dmc-compat-on.cmd` 启用实验，双击 `dmc-compat-off.cmd` 使用同一 exe 的无实验对照。两个版本的 exe 不要互相覆盖后混淆。

当前候选机制：

- 只为真实启动过双枪／霰弹普通射击的持续按枪记录意图，不为勾爪或爆弹枪新增蓄力。
- 原游戏已消费请求、尚未观察到蓄力启动且缓冲已空时，恢复枪长按重试资格；最多每 100 毫秒一次。仍使用游戏原来的长按阈值、技能判断和蓄力动作，不伪造按键松开／按下。
- 只为对应蓄力入口匹配临时使用人类模式，返回后恢复事件模式；只在这条重试路径放行根入口的 RangedDenied 和匹配蓄力枪种的武器选择条件。
- 已观察到蓄力标志非零时停止补发；枪键松开、角色／输入对象变化或可识别的死亡状态时结束本轮资格。合法释放交给原游戏。
- 跳跃、近战消费规则不改变；不全局禁止清理，不强留旧射击节点，不缓存归池输入事件，不直接把蓄力标志写成 1。

目标是枪持续按住时，快速接攻击也不能漏掉蓄力启动，并最终覆盖战斗中的模式和武器切换。**当前是第一份候选，不是已验证实现了“任何情况下绝不打断”**：已启动蓄力被某动作真正终止时，恢复重试可能重新开始计时；换枪后的释放动作兼容性也尚待实测。死亡、场景卸载不应强留动作。不能仅凭画面效果判断完整蓄力状态被保留。

只对 `CUSA01022` / `01.03` 启用，并核对六个代码入口的完整指令前缀；运行时再核对 BoolVariable opcode。任何不匹配都不启用实验。`shad_log.txt` 中搜索 `[DMC COMPAT]` 可区分启用、禁用、普通射击意图和首次补发。没有这些实际执行记录不能宣称补丁已生效。

建议先不录 F9：正常开枪／松枪、早接剑、按枪后接天使／恶魔攻击、反向先扳机后按枪的勾爪。确认基础正常后再检查换枪和被击中。失败时保留普通日志；不必一开始重录大量成功样本。异常先用 off 启动器对照，备份存档，不建议首次测试直接用于长时间正式进度。

## ROOTCAUSE-diagnostic：追模拟器源头

编译 `ENABLE_DMC_CHARGE_COMPAT=OFF`，完全不含兼容改写。保留现有 1774f9b3 的输入、入口、节点、缓冲和重放探针，继续用于原始行为证据。这次没有声称新增根因发现。

F9 开始／停止，沿用成功、早接剑失败、持续按枪松扳机后恢复三个对照。重日志仍可能扰动帧时间，不适合当正常游玩版本。

兼容实验成功只说明该策略能绕过症状，不能证明模拟器根因，也不能替代同版本实机对照。

## 安装范围

两份产物均仅打包 exe、说明与辅助脚本，不是完整安装包。使用前保留原 exe 和已有依赖；缺少 DLL 或原目录来自不兼容发行版时，仅换 exe 不保证可运行。以 `EDITION.txt` 与 `SHA256.txt` 区分包。
