# DmC 专用实验与根因诊断：两个独立版本

仅针对当前 fork 的 Windows 实验分支。兼容改动不是通用模拟器修复，不准备作为上游通用输入行为提交。原始游戏文件不修改。

## 第一版失效与入口修正

`ad7dddb0` 的构建已成功，但用户普通日志显示 `Bool opcode mismatch; experiment disabled`，且没有意图／重试记录；因此这次没有验证到兼容重试实际执行。第一版误将 `0x58880` 作为 BoolVariable 的入口。

重新追踪解释器初始化：`0x6daa8` 将表基址设为 `0x3960040`；`0x6e115` 从 `0x2f975e8` 读取函数成员指针（重定位目标 `0x55b90`、调整值0），`0x6e12a` 写入表偏移 `0x2d0`，即 opcode `0x2d`。修正版挂钩 `0x55b90`，保留运行时检查；没有删除保护强行启用。

普通日志增加有界阶段记录：入口验证、枪长按属性识别、射击意图、控制器字段、已有缓冲、首次重试、蓄力事件条件及入口选中、charge 标志非零。它们用于确认实际执行阶段，不代表已经证明所有动作和计时都正确。诊断版不受这次修正影响。

## 兼容版性能修订

用户反馈入口修正版本严重卡顿。源码检查发现：通用赋值挂钩的512槽直接映射缓存容易反复失效；名称、类型及字段反射查找包含多次 Windows 内存查询。没有用户机器的性能采样，不能声称已经测定各部分耗时比例。

性能修订保留六个入口及原有版本／opcode保护，调整高频路径：

- 名称、类型、字段查询的成功和失败结果均缓存，不再使用容易覆盖的字段直接映射槽。
- 通用赋值先筛选函数名 `OnStart`，再筛选普通双枪／霰弹动作；无关赋值不再解码35字节的表达式。当前仍是通用入口转发，并不是已经消除了全局挂钩成本。
- 定位到双枪／霰弹共用的 `DVAction_Dante_RangedAttack.OnStart` 确切赋值地址后，其他赋值仅比较地址并直接转发，不再查询名称缓存。即使角色字段或按枪资格不符合，也会完成此地址定位，避免一直保持全局发现模式；角色／输入对象变化后重新识别。
- 已识别的长按消费属性及PlayerTick入口在线程间共享；无关线程也能直接排除其他布尔变量，不必各自长期重复发现。
- 枪长按属性识别后，无关布尔变量直接转发；PlayerTick及控制器身份不再每帧重新通过反射遍历确认。
- 没有枪意图、非枪事件、非Held事件直接转发，不查询持续按枪状态或遍历蓄力入口。
- 当前回调借用的活跃事件／链接数组采用与已核对原函数一致的字段读取；角色、输入及待处理缓冲的易变状态仍保留内存检查，没有全局关闭 `Read` 的保护。
- 蓄力目标分类按定义身份及本次射击代数缓存；对象变化或新普通射击使旧分类失效。嵌套选择器无关事件也临时退出兼容作用域，返回后恢复。

这些是静态可核查的开销削减，实际帧率及蓄力效果仍未验证；优先检查游玩流畅度，不要求额外F9重录。关闭实验需完全退出并通过off启动器重启。

## NTPawn 上下文字段修正

63985首测普通日志确认 BoolVariable 入口验证成功、消费属性已识别、射击赋值地址已定位，但没有射击意图、重试或蓄力入口记录。不能把这轮称为实际重试后仍被拒绝。

核对游戏包得到：DVPawn_Dante → DVPawn_Dante_Native → DVPawn_Player → DVPawn → NTPawn → NTAnimatedActor → NTGameObject → Engine.Actor。它不是 Engine.Pawn。原兼容代码假设的 `Controller`、`Health` 不适用于这里：`NTPawn.SetController` 明确写入 `m_Controller`（对象）及 `m_NTController`（接口），生命字段是 `NTPawn.m_Health`（FloatProperty）。

修正为读取 `m_Controller`、按float读取 `m_Health`，不更改原游戏文件。此前缺失Controller字段足以阻止射击意图成立；查找不存在字段也是冷路径开销来源。但普通日志没有帧时间，本轮附近同时存在shader/pipeline编译，不能断言全部冻结都是同一原因。

增加只在类型／角色上下文变化及首次射击地址发现时输出的字段偏移和查找耗时（微秒），不是逐帧日志。用于确认字段获取及冷查找成本；不代表已验证流畅度、原始蓄力bug或模拟器根因。

## 持续近战下的重试资格修订（工作区候选）

用户反馈1975f401字段修正版能在停止攻击后恢复蓄力，但持续攻击时不启动。`E:\log\shad_log.txt` 已确认该版本的枪意图和重试确实执行；没有蓄力入口选中记录，之后才出现蓄力标志。普通日志不能精确标注停止攻击时刻。

源码复查发现重复保护原来要求整个聚合缓冲为空，这也会让近战等其他输入挡住枪重试。候选改为只在缓冲已有同一个枪描述符、type=Held的请求时保留等待；其他输入不阻止枪重试。最多扫描64项，读失败或超过限额时不补发；不移除近战请求，不复用／保留缓冲事件指针，不改变100ms限速。

普通日志区分 `Existing held-gun request retained` 与 `Other buffered inputs do not block gun retry`，每个普通射击意图最多记录一次。这只是修正补丁自身过严的条件，不代表已经证实本轮迟启动根因；已有枪Held请求在缓冲中一直等待时，本候选仍不会强行重放它。

## 1975f401之后的入口／冷查找修订

该日志实测控制器、角色字段及首次射击上下文查找分别耗时约9.14、11.43、10.81秒，补丁冷查找是长冻结的确定来源之一。新的字段遍历只在单次查找内复用已检查可读的内存区间、只读取一次名称表信息，并设4096个字段的总上限；返回后丢弃区间快照，不给角色／输入等易变状态永久缓存可读资格。首次射击直接使用已验证赋值字节码携带的 `m_Dante` 属性偏移，并与当前PlayerTick角色匹配，不再查找角色控制器字段。实际耗时改善仍需运行记录确认。

静态核对原生选择器发现兼容代码的数组偏移有误：`set+0x78/0x80` 是事件条件，不是动作链接；真正的链接位于 `set+0x60/0x68`。修正后才能正确识别包含对应蓄力动作的选择集合。这是补丁自身缺陷，不是已找到shadPS4原始根因。

另核对到图级条件会在调用选择器前先执行。兼容放行补充这个确切调用点，但仅限同一角色、枪仍按住、尚未蓄力、原枪种Held事件，以及 `RangeAttacksRoot.RangedDenied`；不会把武器条件或其他技能条件全局放行。普通日志每轮最多记录一次实际改写的拒绝条件，用于区分图级提前拒绝与链接选择中的拒绝。该调用点在本轮日志中是否拒绝尚未证实，属于有边界的兼容实验。

## COMPAT-experimental：先测试玩法

### 勾爪起手、松模式键后持续按枪的补充入口

用户确认d37ca0d5总体可用，但报告：先按模式扳机再按枪进行勾爪，枪不松，松扳机后快速接普通近战，又可能不启动蓄力。`E:\log\shad_log.txt`（521166字节，revision d37ca0d5）包含已生效的普通射击兼容路径，但无逐键时序，不能独立给该失败样本定位；也不能据此判断实机是否同样如此。

源码原先只从双枪/霰弹普通射击建立兼容意图，确实没有勾爪起手入口。本修订在PlayerTick观察同一轮持续按枪：实际PlayMode处于Demon/Angel时仅记录资格、保留勾爪；回到Normal后按当前m_ActiveRangedWeapon建立双枪/霰弹意图，接入已有重试/蓄力选择机制。模式与武器均取游戏字段，不硬编码物理扳机映射。已核对游戏枚举Normal=0/Demon=1/Angel=2，武器EbonyIvory=0/Shotgun=1，其余不启用本入口。

枪松开、角色/输入上下文改变会清除该资格；武器未支持或字段读取失败不启用。不会在模式键仍使角色处于天使/恶魔模式时，为一个新的勾爪起手强行增加蓄力。保留模式期间观察到的枪Held聚合器引用以便回到人类模式后重试，但不保留池化事件对象、不改游戏文件、不增加全局钩子。

新增普通标记 `Held gun intent after returning to human mode`；未要求F9。实际过渡效果仍需运行验证，本次不处理跳砍漏攻击，也不改变跳跃/近战的消费规则。已按住枪开过普通射击的既有兼容路径保持原策略。

### c2dfd662卡顿反馈后的热路径修订

`E:\log\shad_log.txt`（942605字节，revision c2dfd662）已确认：控制器/角色/射击上下文查找分别为54057、25675、17159微秒，原来的秒级冷查找已降低；也已有蓄力入口接受、选中和charge flag记录。用户仍报告开霰弹枪后严重卡顿，不能据此宣称玩法或性能正常。日志同时有shader/pipeline编译，没有完整帧耗时或CPU采样，不能断言全部卡顿属于哪个环节。

本次只削减兼容热路径的重复内存查询：把原来仅字段遍历内复用的可读区间检查扩展到单次兼容回调，嵌套回调共享，最外层返回即销毁；每次仍重新读取字段值，不缓存按键、生命、蓄力值或缓冲内容。没有跨帧永久复用可读区间，也没修改全局Read或诊断版。已进入蓄力时先退出重试判断，减少不必要读取；根Token名称判断采用已有名称缓存。无关通用赋值在创建作用域前先快速排除。

每线程最多8条 `Slow memory checks`，只有单次回调累计内存查询耗时达到4ms才输出，列出scope/reads/queries/query_us。这不是F9逐帧追踪，也不是完整CPU性能采样。修订仅为有依据的开销削减，实际改善尚待验证；保留原兼容功能及off启动器对照。

专用编译开关 `ENABLE_DMC_CHARGE_COMPAT=ON`。此产物默认启用；`SHADPS4_DMC_COMPAT=0` 可禁用，必须重新启动模拟器。与 F9 无关。不安装重诊断探针，游玩时不要按 F9。

把 exe 和两个 cmd 放入现有模拟器目录（先备份旧 exe）。双击 `dmc-compat-on.cmd` 启用实验，双击 `dmc-compat-off.cmd` 使用同一 exe 的无实验对照。两个版本的 exe 不要互相覆盖后混淆。

当前候选机制：

- 只为真实启动过双枪／霰弹普通射击的持续按枪记录意图，不为勾爪或爆弹枪新增蓄力。
- 原游戏已消费请求、尚未观察到蓄力启动且缓冲无相同枪Held请求时，恢复枪长按重试资格；最多每 100 毫秒一次。仍使用游戏原来的长按阈值、技能判断和蓄力动作，不伪造按键松开／按下。
- 只为对应蓄力入口匹配临时使用人类模式，返回后恢复事件模式；只在这条重试路径放行根入口的 RangedDenied 和匹配蓄力枪种的武器选择条件。
- 已观察到蓄力标志非零时停止补发；枪键松开、角色／输入对象变化或可识别的死亡状态时结束本轮资格。合法释放交给原游戏。
- 跳跃、近战消费规则不改变；不全局禁止清理，不强留旧射击节点，不缓存归池输入事件，不直接把蓄力标志写成 1。

目标是枪持续按住时，快速接攻击也不能漏掉蓄力启动，并最终覆盖战斗中的模式和武器切换。**当前是第一份候选，不是已验证实现了“任何情况下绝不打断”**：已启动蓄力被某动作真正终止时，恢复重试可能重新开始计时；换枪后的释放动作兼容性也尚待实测。死亡、场景卸载不应强留动作。不能仅凭画面效果判断完整蓄力状态被保留。

只对 `CUSA01022` / `01.03` 启用，并核对六个代码入口的完整指令前缀；运行时再核对 BoolVariable opcode。任何不匹配都不启用实验。`shad_log.txt` 中搜索 `[DMC COMPAT]` 可区分启用、禁用、普通射击意图和首次补发。没有这些实际执行记录不能宣称补丁已生效。

建议先不录 F9：正常开枪／松枪、早接剑、按枪后接天使／恶魔攻击、反向先扳机后按枪的勾爪。确认基础正常后再检查换枪和被击中。失败时保留普通日志；不必一开始重录大量成功样本。异常先用 off 启动器对照，备份存档，不建议首次测试直接用于长时间正式进度。

## ROOTCAUSE-diagnostic：追模拟器源头

编译 `ENABLE_DMC_CHARGE_COMPAT=OFF`，完全不含兼容改写。保留现有 1774f9b3 的输入、入口、节点、缓冲和重放探针，继续用于原始行为证据。这次没有声称新增根因发现。

F9 开始／停止，沿用成功、早接剑失败、持续按枪松扳机后恢复三个对照。重日志仍可能扰动帧时间，不适合当正常游玩版本。

兼容实验成功只说明该策略能绕过症状，不能证明模拟器根因，也不能替代同版本实机对照。

## 安装范围

两份产物均仅打包 exe、说明与辅助脚本，不是完整安装包。使用前保留原 exe 和已有依赖；缺少 DLL 或原目录来自不兼容发行版时，仅换 exe 不保证可运行。以 `EDITION.txt` 与 `SHA256.txt` 区分包。
